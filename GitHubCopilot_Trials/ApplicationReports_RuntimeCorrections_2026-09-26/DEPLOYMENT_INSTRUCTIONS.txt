PURPOSE
-------
This consolidated package is rebased against the synchronized source supplied after
ErrorsAterReports.txt. It completes the application-level Reports page and corrects

CONFIRMED SOURCE/DEPLOYMENT MISMATCH
------------------------------------
The synchronized source did not contain the operational Reports files or the complete

CORRECTIONS INCLUDED
--------------------
- Removes all merge markers from App.razor while preserving the data-entry and website
  stylesheets plus the asset-detail chart script from both sides of the merge.
- Uses Dapper/claims instead of circuit-scoped UserManager reads during rendering.
- Initializes a missing active tenant even when another component has already populated
  the authenticated user session.
- Holds tenant-aware page content behind a tenant-session readiness gate.
- Corrects dashboard assessment queries to use CaseNumber, CreatedBy, StatusId,
  AssessmentFinishDate and the actual assessment dashboard route.
- Corrects top-performer joins from tblApplicationUsers.Id to UserId.
- Prevents the operational report WHERE keyword and first predicate from being
  concatenated as invalid SQL (`WHEREassessment`).
- Adds the missing announcement and alert-dismissal tables.
- Includes the complete application-level Reports page and its tenant authorization
  dependencies.

AUTHORIZATION
-------------
- The page requires an authenticated user.
- Every query requires an active tenant membership and active subscription.
- Tenant Owner and Tenant Administrator can report across the active tenant.
- Branch Manager and Viewer see only assessments created by them or explicitly
  granted to their membership, matching Broad Tenant Authorization rules.
- Billing Manager alone does not receive operational reporting access.
- All SQL enforces TenantId and record-scope predicates before applying filters.
- The MainLayout Reports link is hidden when the active membership has no
  operational read permission.
- Exports and email contain only the already-authorised filtered result set.

IDENTITY DBCONTEXT CONCURRENCY CORRECTION
-----------------------------------------
Blazor components share scoped services for the lifetime of a circuit. The old
MainLayout and profile dropdown could start concurrent UserManager queries against
the same scoped IdentityDbContext during initial rendering, producing:

  A second operation was started on this context instance before a previous
  operation completed.

The included correction:
- Uses IUserRepository's independent Dapper connection for render-time current-user
  profile reads in AuthenticationService.
- Removes render-time UserManager queries from ProfileDropdownComponent.
- Reads the displayed Identity role from the authenticated principal's role claim.
- Preserves UserManager for sequential Identity write operations such as login,
  registration, password and account management.
- Preserves tenancy initialization in MainLayout before resolving report access.
