VIABILITYIQ IDENTITY USER CONTEXT CORRECTIONS
Package date: 2026-09-30

PURPOSE
-------
This package corrects the authenticated user's session timestamps, tenant branch,
profile data, and tenant-role display.

CHANGES
-------
1. Home page session information
   - Records PreviousLoginAt before LastLoginAt is updated during successful sign-in.
   - Records LastLogoutAt after secure sign-out completes.
   - Displays Previous sign-in and Last sign-out independently.
   - Uses local time for older absolute timestamps.
   - Removes the fabricated two-hour fallback used when no login existed.

2. Correct tenant branch
   - Loads the branch from the active tblTenantMembership.DefaultBranchId.
   - Resolves and displays the branch name from the active tenant's tblBranch row.
   - No longer displays the global tblApplicationUsers.BranchId or "Default Branch".

3. My Profile
   - Changes the profile link to /identity/profile.
   - Loads first name, last name, email, telephone, department, job title, province,
     address, city, country, and date of birth from the authenticated ApplicationUser.
   - Saves editable profile fields through IAuthenticationService.
   - Keeps email read-only and does not alter tenant membership branch or roles.
   - Uses ToastService for profile-update success and failure feedback.

4. Profile role display
   - Loads roles from the active tenant membership rather than the global Identity
     "User" role.
   - Ranks Tenant Owner, Tenant Administrator, Branch Manager, Billing Manager, then
     Viewer.
   - Displays the highest-ranked role prominently and remaining tenant roles below it
     in smaller text.
   - Retains Identity-role fallback only if tenant context cannot be resolved.

DATABASE
--------
Before deploying application files, run:

  Files\DatabaseScripts\2026-09-30_IdentitySessionTimestamps.sql

The script is idempotent and adds nullable columns to dbo.tblApplicationUsers:

  PreviousLoginAt DATETIME2(7)
  LastLogoutAt DATETIME2(7)

Existing users will show "First sign-in" and "Not recorded" until new sign-in/sign-out
events populate these fields.
