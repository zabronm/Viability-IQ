MAIN LAYOUT ASSESSMENT CONTEXT AND NAVIGATION CHANGE
====================================================

SessionService is scoped and stores its values only in memory. Its AssessmentId
is lost when a browser refresh, direct URL, new tab, or other operation creates
a new Blazor circuit. The parent assets route therefore carries AssessmentId as
its durable source:

    /assessment/assets/{AssessmentId}

NAVIGATION LINK - REQUIRED
--------------------------

When adding the Assets link to MainLayout_Assessment.razor, do not use a
fixed href such as:

    href="assessment/assets"

Use the current assessment ID:

    @if (SessionService.AssessmentId is long assessmentId && assessmentId > 0)
    {
        <NavLink class="fa-nav-item"
                 href="@($"assessment/assets/{assessmentId}")">
            <div class="nav-icon-avatar-round">
                <i class="bi bi-building"></i>
            </div>
            <span class="footer-main-text-sm">Assets</span>
        </NavLink>
    }

For example, assessment 125 must navigate to:

    /assessment/assets/125

This remains correct after refreshing the assets page because the ID is
reconstructed by the Blazor router rather than read only from SessionService.
AssessmentAssetsPage passes the resolved ID to both tab components.

OPTIONAL CASCADING FALLBACK
---------------------------

The layout can also pass its current in-memory value to parameterless assessment
pages. In MainLayout_Assessment.razor, find:

    <main class="fa-main-content-surface @(isSidebarCollapsed ? "expanded" : "")">
        <div class="content-body-padding">
            @Body
        </div>
    </main>

Replace it with:

    <main class="fa-main-content-surface @(isSidebarCollapsed ? "expanded" : "")">
        <div class="content-body-padding">
            <CascadingValue TValue="long?"
                            Name="CurrentAssessmentId"
                            Value="SessionService.AssessmentId"
                            IsFixed="false">
                @Body
            </CascadingValue>
        </div>
    </main>

Why this is useful:

1. MainLayout_Assessment already injects the correct SessionService and displays
   its CaseNumber.
2. The cascading value passes that layout-owned AssessmentId to every assessment
   page rendered through @Body.
3. IsFixed="false" allows the value to update when the user switches assessment.
4. AssessmentAssetsPage resolves context in this order:
   route AssessmentId, cascaded AssessmentId, injected SessionService.
5. AssessmentAssetSummaryPage and AssessmentAssetDetailsPage receive the
   resolved value from AssessmentAssetsPage as a normal component parameter.

AssessmentAssetsPage receives it with:

    [CascadingParameter(Name = "CurrentAssessmentId")]
    public long? CascadedAssessmentId { get; set; }

The cascading change is a fallback. The parameterized navigation link is the
reliable fix for refreshes and newly created circuits. The detail component no
longer has an @page route of its own.
