IMPLEMENTED CORRECTIONS
-----------------------
1. MONTH LABELS
   Razor expressions following the literal "M" are now explicitly enclosed in
   parentheses. Values render as "M1", "M4", and similar instead of showing
   text such as "M@adjustment.EffectiveStartMonth".

   This correction also covers minimum-cash month labels in KPI and sensitivity
   result output.

2. COMPLETE PRINT / SAVE PDF OUTPUT
   Both the page-level and GroqCloud-tab Print / Save PDF buttons call the same
   complete-report print implementation.

   The print implementation creates an isolated print document containing the
   complete active Sensitivity Analysis tab. It is therefore not constrained by
   the application's fixed-height workspace or nested scroll position.

   The result:
   - Includes content below the visible screen.
   - Paginates long reports.
   - Removes navigation, controls, and scrollbars.
   - Preserves component styling and financial status colors.
   - Avoids splitting KPI cards, charts, summaries, and recommendation rows
     where the browser supports print break rules.

   "Complete report" means the complete currently selected tab. Hidden tabs are
   not included because they represent different analyses and may not yet have
   been calculated.

3. KPI VALUE COLORS
   Only the primary value is colored; card labels and explanations remain
   neutral for readability.

   Monetary performance KPIs:
   - Red / critical: value is negative.
   - Amber / average: value is non-negative but below 90% of baseline.
   - Black / good: value is between 90% and below 110% of baseline.
   - Green / very good: value is at least 110% of baseline.

   Gross margin:
   - Red / critical: below 0%.
   - Amber / average: 0% to below 20%.
   - Black / good: 20% to below 30%.
   - Green / very good: 30% or higher.

   Funding shortfall:
   - Red / critical: a funding shortfall exists.
   - Green / very good: no funding shortfall exists.

   These rules are applied to KPI cards in both Scenario Builder results and
   the GroqCloud report.

DEPLOYMENT
----------
1. Back up the four target files listed above.
2. Stop the application or IIS application pool.
3. Open this package's Files directory.
4. Copy each file to the matching production-relative path.
5. If any target file contains later local changes, merge this package rather
   than overwriting those changes.
6. From the solution root, run:

   dotnet build .\ViabilityIQ.sln --no-restore

   Run dotnet restore first only if the build reports missing restored assets.

7. Restart the application or recycle the IIS application pool.
8. Perform a hard browser refresh so the updated JavaScript is loaded:

   Ctrl+F5

   If a reverse proxy or CDN caches static assets, purge or invalidate
   /scripts/assessmentPagePrint.js.
