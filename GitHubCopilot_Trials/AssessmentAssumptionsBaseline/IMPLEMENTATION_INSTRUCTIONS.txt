ASSESSMENT ASSUMPTIONS & BASELINE - IMPLEMENTATION
==================================================

Scope
-----
This package refactors AssessmentSettingsPage into a four-tab lightweight assumptions
module and adds readiness validation. It does NOT connect the new assumptions to, or
change, the projection engine.

Prerequisites
-------------
1. Back up the application and database.
2. Deploy first to a test environment.
3. Confirm dbo.tblAssessments and dbo.tblAssessmentDebtorsCreditorsProfile are the
   production table names before running the SQL script.

Database deployment
-------------------
Run:
  Files\ViabilityIQ.Modules\Database_Sql\AssessmentProjectionAssumptions.sql

The script:
- Creates dbo.tblAssessmentProjectionAssumptions when absent.
- Enforces one active assumptions record per assessment.
- Adds percentage, month and VAT-frequency validation constraints.
- Backfills one draft assumptions record per existing assessment.
- Seeds BadDebtRate from the latest active debtor/creditor profile when available.

Application deployment
----------------------
Copy every file beneath Files into the corresponding path at the solution root,
preserving the directory structure.

Important:
- AssessmentSettingsPage.razor.cs is deliberately not replaced.
- Existing Sales Categories, VAT, opening balances, debtor/creditor profiles,
  director wages, loans and assets remain authoritative.
- The open-generic IGenericDataRepository registration already resolves the new entity;
  no DI registration is required.

Verification
------------
1. Build ViabilityIQ.sln.
2. Open /assessment/settings/{AssessmentId}.
3. Verify all four tabs render:
   Opening Position; Sales & Working Capital; Expenses & VAT; Funding & Assets.
4. Save each lightweight assumptions section and reload the page.
5. Confirm one active row exists in dbo.tblAssessmentProjectionAssumptions.
6. Confirm the readiness score updates after an assumptions save.
7. Verify existing Sales Category and loan off-canvas forms still open.
8. Verify the Assets link opens /assessment/assets/{AssessmentId}.
9. Print the readiness report using its printer button.

Data collection
---------------
Use ASSUMPTIONS_DATA_COLLECTION_TEMPLATE.csv with the assessor/business owner before
data capture. READINESS_RULES.txt documents every automated readiness check.

Rollback
--------
Restore the prior AssessmentSettingsPage.razor and .razor.css files. Remove the new
AssumptionComponents files. The new SQL table can remain safely unused; only drop it
after confirming no captured assumptions data is needed.

Build evidence
--------------
Integrated isolated solution build:
  Build succeeded with 0 errors.
  Existing solution warnings remain and are not introduced as functional blockers.
