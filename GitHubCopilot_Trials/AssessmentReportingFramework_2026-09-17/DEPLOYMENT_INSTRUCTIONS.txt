ASSESSMENT REPORTING FRAMEWORK - DEPLOYMENT
Generated: 2026-09-17

PURPOSE
This isolated package replaces the mock AssessmentReportsPage with four live reports:
Assessment Summary, Profit & Loss, Cashflow and Balance Sheet. It also adds a reusable
report output menu, browser PDF printing, genuine Open XML workbooks, confirmed email
delivery and report activity auditing. Definitions remain fixed code metadata and can be
extended with ReportScope.System for future administrative reports.

PRE-DEPLOYMENT
1. Back up the application and database.
2. Confirm the effective baseline already contains AuthoritativeOpeningBalances,
   Assessment Assumptions, Sensitivity Analysis and the central cashflow projection.
3. Review MANUAL_EXISTING_FILE_MERGE.txt. Do not blindly replace DI, App.razor or
   appsettings files.

Run, with a deployment identity allowed to create tables/indexes:
  Files\ViabilityIQ.Infrastructure\Data\Migrations\20260917_CreateReportActivity.sql
The script is idempotent. Report output remains available when audit storage is unavailable,
but the UI and logs explicitly disclose that the activity was not audited.

EMAIL CONFIGURATION
Configure secrets through environment variables or user secrets, never committed JSON:
  EmailSettings__SmtpServer
  EmailSettings__Port
  EmailSettings__SenderAddress
  EmailSettings__SenderPassword
  EmailSettings__EnableSsl

as an explicit configuration failure and logged without the password.

VALIDATION
  dotnet build .\ViabilityIQ.sln --no-restore --nologo
Then manually verify:
1. Open /assessment/reports/{AssessmentId} for a complete and an incomplete assessment.
2. Generate all four reports for M1-M12 and a smaller valid month range.
3. Confirm statement figures reconcile to the current cashflow projection.
4. Export every report to .xlsx and open it in Excel/LibreOffice.
5. Use Export to PDF and confirm only the report prints, portrait for Summary and landscape
   for statements.
6. Configure a non-production SMTP test account; confirm email only sends after form submit,
   the HTML body and .xlsx attachment arrive, and the displayed reference matches logs.
7. Query dbo.tblReportActivity and verify Generated/PdfExported/ExcelExported/Email activity.
Do not send a real email as part of automated deployment validation.

KNOWN LIMITATIONS
- PDF uses the browser's print/save-PDF dialog; no PDF bytes are attached to email.
- Email intentionally attaches Excel and includes a formatted HTML summary.
- Business profile output is limited to verified fields currently present in Assessment and
  Business. Industry names/program/application facts are omitted rather than invented.
- VAT is represented in cashflow and other-current-liability fields available in the central
  model; residual equity is explicitly disclosed as a balancing amount.
