VIABILITYIQ TENANT USER AND ROLE MANAGEMENT
Package date: 2026-09-29

PURPOSE
-------
This package completes the two Security Settings destinations already linked from:

  /settings/settings

Routes implemented:

  /settings/users
  /settings/roles

WORKFLOW
--------
Tenant Owner and Tenant Administrator can:
- Create a ViabilityIQ account directly.
- Select a branch.
- Allocate one or more tenant roles.
- Add an existing ViabilityIQ account to the active tenant.
- Suspend, reactivate or remove a tenant membership.
- Re-add a previously removed member.
- See active users compared with the subscribed seat quantity.

For a new account:
1. A cryptographically generated temporary password is created.
2. The account receives the global Identity role User when that role exists.
3. An active tenant membership and the selected tenant roles are created.
4. The temporary password is sent using the existing EmailSettings SMTP configuration.
5. The user is redirected to Change Password after first sign-in.
6. All other application routes remain blocked until the password is changed.

If welcome-email delivery fails, the new account and tenant membership are rolled back.
The temporary password is never logged or shown in the UI.

SUPPORTED TENANT ROLES
----------------------
- Tenant Owner
  Protected. Created and assigned during tenant provisioning and cannot be reassigned
  through these pages.
- Tenant Administrator
- Branch Manager
- Viewer
- Billing Manager

Multiple roles can be assigned to one tenant member.

AUTHORIZATION
-------------
- Only Tenant Owner and Tenant Administrator can load or modify tenant users and roles.
- Role and user links are hidden from other tenant members on /settings/settings.
- Every service operation independently validates the active tenant role.
- All membership, role and branch reads/writes include the active TenantId.
- Tenant Owner membership and role are immutable in these pages.
- Administrators cannot suspend or remove their own active membership.
- Subscription SeatQuantity is enforced for new and reactivated active members.
- Standard Plan tenants normally have one seat and therefore cannot add another active
  member unless the subscription seat quantity is increased.

That separate application-layer file contains the Gemini and Groq registrations.

EMAIL CONFIGURATION
-------------------
The feature reuses the existing settings:

  EmailSettings:SmtpServer
  EmailSettings:Port
  EmailSettings:EnableSsl
  EmailSettings:SenderAddress
  EmailSettings:SenderPassword

The user is not created when SMTP delivery fails. Verify these settings before testing.

REPORTING INTEGRATION
---------------------
OperationalReportsService now resolves an advisor's branch from:

  tblTenantMembership.DefaultBranchId

instead of the global tblApplicationUsers.BranchId. This keeps branch reporting correct
when an existing account belongs to more than one tenant.

12. Reactivate the user.
13. Remove and re-add the user using the same email.

15. Sign in as Branch Manager, Viewer and Billing Manager and confirm the two Security
