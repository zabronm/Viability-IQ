ASSESSMENT ASSUMPTIONS AND FORM REFINEMENT
==========================================

Purpose
-------
1. Clarifies the authoritative, read-only opening stock and depreciation values.
2. Restores the Debtors/Creditors ageing profile layout.
3. Identifies amortization as the default loan repayment method.
4. Improves the loan repayment month table.
5. Brings AssessmentAssetsFormComponent into the shared viq form design.

Calculation findings
--------------------
- Opening stock is not independently entered in assumptions. It is calculated from
  active Sales Category OpeningStock values.
- The cash-flow projection uses that total as Month 1 opening stock and rolls stock
  forward with monthly purchases less cost of goods sold.
- Opening accumulated depreciation is not independently entered in assumptions. It
  is calculated from registered assets' OpeningAccumulatedDepreciation values.
- Projected depreciation is calculated monthly by IAssetDepreciationEngine from the
  registered asset data. It is used in projection depreciation, EBIT, profit metrics,
  asset carrying values, and balance-sheet outputs.
- The assumptions Opening Balances component displays all three values as read-only
  authoritative totals. Only genuinely independent balances remain editable.

UI changes
----------
- Debtors/Creditors uses readable typography, balanced two-column ageing panels,
  consistent inputs, responsive stacking, and corrected entry-mode controls.
- Assessment Loan displays a clear note that reducing-balance amortization is the
  default repayment schedule.
- Loan Repayment uses a sticky, scrollable schedule with aligned numeric columns,
  clear locked values, highlighted editable extras, and a visible totals row.
- AssessmentAssetsFormComponent now uses the same viq sections, controls, busy state,
  responsive month grid, calculated total, and green action footer as other forms.

Deployment
----------
1. Stop the application.
2. Copy the contents of Files into the production solution root, preserving folders.
3. Confirm wwwroot/css/data-entry-forms.css from the shared form-theme package is
   already deployed.
4. Rebuild and publish using the normal production process.
5. Start the application.

No database changes are required.
