VIABILITYIQ IDENTITY DBCONTEXT CONCURRENCY FIX
Package date: 2026-09-26

ERROR CORRECTED
---------------
System.InvalidOperationException:
A second operation was started on this context instance before a previous
operation completed.

ROOT CAUSE
----------
In Blazor Server, scoped services live for the complete user circuit. MainLayout,
ProfileDropdownComponent and page components could initialize concurrently and
use the same scoped UserManager. UserManager's Entity Framework store uses the
same scoped IdentityDbContext, which does not support concurrent operations.

CORRECTION
----------
1. AuthenticationService.GetCurrentUserAsync now:
   - Validates the NameIdentifier claim.
   - Uses the existing IUserRepository Dapper query.
   - Receives an independent database connection for each call.
   - Does not use UserManager for render-time profile reads.

2. ProfileDropdownComponent now:
   - Uses IUserRepository for the optional current profile lookup.
   - Reads the displayed Identity role from ClaimTypes.Role.
   - Does not query UserManager while MainLayout/pages initialize.

UserManager remains available for sequential Identity operations such as login,
registration, password changes and account management.

DEPLOYMENT
----------
Back up and merge/replace:

  -> ViabilityIQ.Database\ServicesMisc\AuthenticationService.cs

Files\ViabilityIQ.Web\Components\Pages\Identity\ProfileDropdownComponent.razor
  -> ViabilityIQ.Web\Components\Pages\Identity\ProfileDropdownComponent.razor

No database migration or service registration is required.
