ASSESSMENT KPI AND SESSION CONSISTENCY FIX
==========================================

Purpose
-------
1. Makes the AssessmentsPage lifecycle KPI cards use the same authenticated-user
   KPI source and formulas as HomePage.
2. Prevents one assessment readiness error from leaving every KPI card at zero.
3. Makes every Recent Assessments open action validate the selected assessment's
   actual module records before populating MainLayout_Assessment indicators.

Prerequisite
------------
Deploy AssessmentWorkflow_2026-09-24 before this package.

Deployment
----------
1. Stop the application.
2. Copy the contents of Files into the production solution root, preserving the
   folder structure.
3. Rebuild and publish using the normal production process.
4. Start the application.

No database changes are required.

Behavior after deployment
-------------------------
- HomePage and AssessmentsPage call the same GetKPIMetricsAsync user-scoped source.
- Draft and In Progress counts use active tblAssessments records and StatusId values.
- The authenticated user is resolved directly if SessionService has not initialized yet.
- Readiness is refreshed independently per assessment; a failed assessment is logged
  without suppressing the remaining KPI values.
- The Recent Assessments row, case-number link, and Open button all use the same handler.
- That handler now uses ValidateAssessmentDataAsync, exactly like AssessmentsPage, for
  Assets, Expenses, Sales, Stock, Reports, Reviews, Debtors/Creditors, and Loans.
